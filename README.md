# 🌌 Nebula — Discord-подобный мессенджер (свой, рабочий)

Полноценный realtime-мессенджер в стиле Discord: каналы, сообщения в реальном времени,
реакции, «печатает…», голосовые комнаты через WebRTC, поиск, список участников.
**Ноль зависимостей** — нужен только Node.js 18+.

> ⚠️ Это **собственный проект с оригинальной айдентикой** (название, логотип, цвета оформления).
> Кодовую базу и интерфейс Discord я не копировал — «копия» здесь означает «такой же по функциональности/UX»,
> а не клон чужого продукта с их логотипами и ассетами. Так проект можно легально выложить в интернет.

## 🚀 Быстрый старт локально

```bash
cd nebula
npm start          # или: node server.js
# открыть http://localhost:3000
```

Проверка версии Node:

```bash
node -v   # нужна 18 или новее
```

Открой два окна браузера (одно — в режиме инкогнито), войди под разными именами — увидишь realtime
сообщения, реакции и голосовую комнату между двумя пользователями.

## 🗂 Структура проекта

```
nebula/
├── server.js        # HTTP-сервер, API, SSE, хранение (Node, без зависимостей)
├── public/
│   ├── index.html   # разметка приложения
│   ├── style.css    # оформление (тёмная тема, адаптив)
│   └── app.js       # клиент: рендер, realtime, WebRTC
├── package.json
├── Dockerfile       # для деплоя в контейнере
├── render.yaml      # Blueprint для Render (деплой одной кнопкой)
└── data.json        # создаётся автоматически (сообщения, каналы)
```

### Как это работает
- **Сообщения**: клиент шлёт `POST /api/messages`, сервер рассылает событие всем через **SSE** (`GET /api/events`).
- **Голос**: сигнализация WebRTC идёт через `POST /api/voice/signal` (SDP/ICE), медиа — напрямую между браузерами (STUN Google).
- **Демонстрация экрана**: кнопка 🖥 в голосовой панели вызывает `getDisplayMedia()` и добавляет видеотрек во все
  активные peer-соединения. Используется **perfect negotiation**, поэтому пересогласование SDP проходит без «glare».
  Новые участники автоматически получают уже идущий стрим, а карточка с видео можно развернуть на весь экран (⛶).
- **Присутствие**: активные SSE-подключения = пользователи онлайн; отключение канала автоматически убирает из голосовой.

# 🌍 Где разместить (бесплатно и дёшево)

## Вариант 1 — Render: **бесплатно, без карты** (самый быстрый старт)

Плюсы: 0 €, деплой из GitHub за 5 минут, HTTPS и поддомен бесплатно, WebSocket/SSE поддержаны.
Минусы: засыпает после ~15 минут простоя (первый заход после сна — ~1 минута),
диск **эфемерный** → `data.json` может сброситься при рестарте/деплое.

Пошагово:
1. Залей проект в GitHub-репозиторий.
2. В [render.com](https://render.com) → **New → Web Service** → подключи репозиторий.
3. Настройки:
   - **Runtime**: Node
   - **Build Command**: `npm install`
   - **Start Command**: `npm start`
   - **Instance Type**: Free
4. Deploy. Через пару минут получишь `https://nebula-chat-xxxx.onrender.com`.

Либо просто положи `render.yaml` в репозиторий и выбери **New → Blueprint** — Render прочитает конфиг сам.

> Лимиты free-плана (2026): 750 часов инстанса в месяц, 512 МБ RAM, 5 ГБ трафика/мес, сон через 15 минут.

**Чтобы данные не пропадали:** либо перейди на платный инстанс и подключи **Persistent Disk**
(диск монтируется, например, в `/opt/render/project/src`), либо держи `data.json` вне контейнера
(например, перейди на VPS или подключи внешнюю БД).

## Вариант 2 — Oracle Cloud «Always Free»: **бесплатно навсегда, круглосуточно**

Самый жирный бесплатный вариант: полноценный VPS, который не засыпает.

- ARM-инстанс **2 OCPU / 12 ГБ RAM**, до 200 ГБ диска — бесплатно бессрочно (лимиты снижены в июне 2026; раньше было 4/24).
- Нужна банковская карта для верификации (с бесплатных ресурсов деньги не списываются).
- Заходишь по SSH, ставишь Node 20, копируешь папку, запускаешь через `systemd`/`pm2`, домен — через Nginx + Let's Encrypt.

```bash
# на сервере (Ubuntu, ARM)
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt-get install -y nodejs nginx
sudo mkdir -p /opt/nebula && sudo chown $USER /opt/nebula
# скопируй файлы проекта в /opt/nebula (scp/rsync/git clone)
cd /opt/nebula && npm start
```

`systemd`-юнит `/etc/systemd/system/nebula.service`:

```ini
[Unit]
Description=Nebula Chat
After=network.target

[Service]
WorkingDirectory=/opt/nebula
ExecStart=/usr/bin/node server.js
Restart=always
Environment=PORT=3000
User=ubuntu

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl enable --now nebula
```

Nginx-конфиг (`/etc/nginx/sites-available/nebula`) — важно отключить буферизацию для SSE:

```nginx
server {
    listen 80;
    server_name chat.example.com;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # SSE / long-lived connections
        proxy_buffering off;
        proxy_cache off;
        proxy_read_timeout 3600s;
    }
}
```

```bash
sudo ln -s /etc/nginx/sites-available/nebula /etc/nginx/sites-enabled/
sudo certbot --nginx -d chat.example.com    # бесплатный HTTPS
```

## 🔒 Что учесть при выкладке в интернет

1. **Это демо, не «боевой» Discord.** Регистрация без пароля: любой может войти под любым ником.
   Для публичного запуска добавьте авторизацию (OAuth/почта) и ограничьте права (кто может удалять сообщения/создавать каналы).
2. **Один инстанс.** Состояние и SSE-клиенты живут в памяти процесса. Нельзя запускать несколько копий за балансировщиком
   без Redis/БД (иначе пользователи на разных инстансах друг друга не увидят).
3. **Голос за NAT.** Сейчас используется только публичный STUN Google. Для работы у части пользователей
   за строгим NAT/корпоративной сетью нужен **TURN-сервер** (например, coturn) — добавьте его в `ICE.iceServers` в `app.js`.
4. **WebRTC требует HTTPS** (или localhost) — на Render/VPS с Certbot это выполняется автоматически.
   В предпросмотре внутри iframe браузер может запретить микрофон и `getDisplayMedia()` (шаринг экрана) —
   это ограничение песочницы, а не приложения. Открой сайт в отдельной вкладке (или на своём домене), и обе
   функции заработают. Если шаринг экрана недоступен, приложение покажет понятное уведомление, а не «сломается».
5. **Резервные копии**: просто копируйте `data.json`.
6. **Модерация**: сообщения пишутся анонимно по нику — для публичного сервера добавьте жалобы/бан-лист.
